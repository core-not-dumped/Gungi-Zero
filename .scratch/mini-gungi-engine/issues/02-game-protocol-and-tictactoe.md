# 02: `games.base.Game` 프로토콜과 틱택토

**What to build:** 틱택토를 `Game` 으로 처음부터 끝까지 둘 수 있다. 프로토콜 모양이 여기서 결정되고, 군의가 아닌 게임으로 검증된다. 같은 테스트 스위트가 앞으로 붙는 모든 게임에 대해 "적합성" 의 정의가 된다.

**Blocked by:** 01

**Status:** ready-for-agent

- [x] `games.base` 가 `Game`·`Position`·`Move` 를 정의한다. `Game` 은 상태를 갖지 않는다
- [x] `Game` 연산: 초기 국면, 합법수, 수 두기, 종료 여부와 결과, 행동 공간 크기, 수→행동 인덱스, 행동 인덱스→수, 합법수 마스크, 정규형(국면과 행동 인덱스 양쪽), 판→텐서, 텍스트 렌더, 텍스트 파싱, `board_key`
- [x] `Position` 은 불변이고 해시 가능하다. `Game` 프로토콜에 `undo` 는 없다
- [x] 판→텐서가 `numpy.ndarray` 를 반환한다. PyTorch 를 import 하지 않는다
- [x] 틱택토가 프로토콜을 구현한다
- [x] 게임에 대해 파라미터화된 적합성 스위트가 있고 틱택토가 통과한다: 합법수 마스크와 합법수 목록 일치, 모든 합법수의 행동 인덱스 왕복, `parse(render(p)) == p`, `정규형(정규형(p)) == p`, 정규형이 합법수 집합을 대응해 옮김, 비종료 국면에는 합법수가 하나 이상, 종료 국면에는 결과가 정해져 있음
- [x] 랜덤 AI 가 합법수 중 균등 무작위로 고르고 시드를 받는다
- [x] 랜덤 대국 스크립트가 틱택토 한 판을 끝까지 돌린다

## Comments

**2026-11-26** — 구현 완료. `games/base.py` 가 `Player`·`Outcome`·`Position`·`Move`·`Game` 을
정의하고, `games/tictactoe.py` 가 룰 엔진 없이 구현한다. 적합성 스위트는
`tests/test_game_conformance.py` 의 `GAMES` 에 게임을 한 줄 더하는 방식이다 — 03 번에서 미니
군의가 같은 스위트를 그대로 받는다. 네 게이트 통과: `pytest`(49 passed) · `ruff check` ·
`ruff format --check` · `pyright`(basic, 0 errors).

**결정 — 행동 인덱스의 프레임.** 모든 연산은 받은 `Position` 의 프레임에서 답한다. 신경망에
쓸 때는 `canonical(p)` 를 먼저 얻어 그 국면에 `encode`·`legal_action_mask`·`legal_moves` 를
쓰면 전부 정규형 프레임이다. 신경망이 고른 인덱스는 `from_canonical_action_index(p, i)` 로
되돌린다. `to_`/`from_` 양방향을 둔 것은 틱택토·군의 모두 멱등/대합이라 한 함수로도 되지만,
"다시 한 번 부르면 역이 된다" 를 호출부가 알아야 하는 설계를 피하려는 것이다.

**결정 — `encode` 는 둘 차례인 쪽 시점이다.** 그래서 `encode(p) == encode(canonical(p))` 가
성질로 성립하고, 호출부가 정규화를 잊어 상대 시점 텐서를 신경망에 넣는 실수가 불가능하다.

**결정 — `Position` 이 `player` 를 저장하고 판에서 유도하지 않는다.** 틱택토는 말 개수로
차례를 유도할 수 있지만, 정규형이 색을 바꾸므로 "선수가 먼저 둔다" 가 깨진 판이 정상적인
국면이 된다. 유도하는 설계는 정규형과 충돌한다. 군의도 같은 이유로 저장한다.

**결정 — `scripts/`.** 랜덤 대국 스크립트는 게임 모듈을 고르는 자리라 `ai/` 안에 둘 수 없다
(`ai/` 는 `games.base` 만 안다). 최상위 `scripts/` 를 합성 루트로 두고 CLAUDE.md 구조와
`pyproject` 의 pyright `include` 에 반영했다. ADR 로 올리지 않았다 — 되돌리기 어려운 결정이
아니고 ADR-0001 의 경계를 건드리지 않는다.

**검토 필요 — `정규형(정규형(p)) == p`.** 이 등식은 후수 차례 국면에서 거짓이다. 정규형은
둘 차례인 쪽을 선수로 만들므로 **멱등**이고(`정규형(정규형(p)) == 정규형(p)`), 티켓이 적은
등식은 `p` 가 이미 정규형인 특수한 경우다. 스위트는 멱등으로 시험한다
(`tests/test_game_conformance.py`). CLAUDE.md 의 속성 테스트 목록에도 같은 문장이 있으니
소유자가 문구를 고칠지 결정해 주면 좋겠다.

**틱택토로는 시험할 수 없는 것.** `board_key` 의 핵심 성질("경로가 달라도 판과 차례가 같으면
같은 키")과 반복 판정은 경로를 들고 다니는 게임에서만 시험된다. 틱택토에는 경로가 없어 공짜로
참이 되므로, 적합성 스위트의 `board_key` 테스트는 약한 성질만 확인하고 그 사실을 테스트
docstring 에 적어 두었다. 진짜 시험은 04 번(종료 규칙)의 몫이다.

**범위.** `ai/episode.py` 의 `Episode` 는 수·최종 국면·결과만 담는다 — 정책 타깃 같은 2단계
학습 데이터는 없다. 랜덤 대국의 반환값에 이름을 주는 것이 `(수 목록, 국면, 결과)` 세 짝을
돌려주는 것보다 낫다고 판단했다. `Outcome.value_for`(학습 타깃)는 소비자가 없어 뺐다 —
부호 규약은 2단계에서 쓸 곳과 함께 정하는 것이 맞다.

**측정(참고).** 틱택토 랜덤 대국 2,000 판: 선수 승 58.3% · 후수 승 28.7% · 무승부 13.1%,
평균 길이 7.66수. 공개된 틱택토 무작위 대국 수치(약 58.5 / 28.8 / 12.7)와 맞는다 — 룰
구현에 대한 저장소 밖 대조점이다. 1단계 측정 보고는 미니 군의 것이고 09 번 티켓이다.
