# 나노 군의의 풀이 (2.5단계)

**시작 국면의 이론값은 선수 승이고 DTM 은 3 이다.** 최대 DTM 은 20 이다.

## 다시 만들기

```
uv run python -m scripts.solve_nano
```

`solutions/nano-gungi.pickle` (약 43 MB, git 제외)을 만들고, 그 파일을 다시 읽어 완벽한 상대끼리 시드 0~9 를 둔 뒤 수치를 JSON 한 줄로 찍는다. 시작 국면의 이론값과 다르게 끝난 대국이 있으면 종료 코드가 1 이다.

읽을 때는 `scripts.solve_nano.load_solution_of(SETUPS["nano-gungi"], path)` 를 쓴다. 수 제한은 파일에 적힌 것을 쓰고, 파일에 적힌 변형 설정이 지금 설정과 다르면 거절한다. **룰 엔진이나 solver 가 바뀐 것은 알아채지 못하므로 그때는 다시 만든다.** 파일은 pickle 이라 직접 만든 것만 읽는다.

## 최대 DTM 과 수 제한

승패는 `DTM ≤ 200 - ply` 일 때만 이루어지고 아니면 무승부다.

- **`ply` 180 까지는 수 제한이 어떤 국면의 값도 바꾸지 않는다.** 최대 DTM 이 20 이다.
- 상태마다 가장 짧은 경로로 처음 닿는 `ply` 는 16 이하다(상태 공간 문서의 최대 깊이). 16 + 20 ≤ 200 이므로 그 국면들의 값은 모두 수 제한이 없을 때와 같다. 시작 국면도 그렇다.
- **DTM 이 남은 수보다 길어 무승부가 되는 국면은 있다.** 실제 규칙으로 같은 판을 세 번 만들지 않고 196수를 두면 아래 국면에 닿는다. 판만 보면 둘 차례인 ▲ 가 6수 만에 지지만, 남은 수가 4 라 이론값은 무승부다. 일회성 스크립트의 깊이 우선 탐색으로 하나를 찾았고, 아래 수순을 처음부터 다시 두어 같은 국면에 닿는 것을 확인했다. 이런 국면이 얼마나 많은지는 세지 않았다.

```
     a       b       c
 4   .       .      ▲帥
 3   .       .       .
 2   .       .       .
 1  ▽帥      .      ▽大
차례: ▲   ply: 196
```

## 선수 필승 수순

```
     a       b       c
 4   .      ▽帥     ▽大
 3  ▽兵      .       .
 2   .       .      ▲兵
 1  ▲大     ▲帥      .
차례: ▲   ply: 0
```

- 첫 수 9개 중 이기는 것은 둘이다. `a1-a3^`(DTM 3, ▲大 가 ▽兵 위에 쌓는다)와 `a1-b2`(DTM 5). 나머지 일곱은 진다.
- `a1-a3^` 뒤에 ▽ 의 합법수는 7개이고, 어느 것을 두어도 ▲ 가 다음 수에 帥 를 잡는다.
- 시작 국면의 강제승은 실제 게임 위의 탐색으로도 확인한다. 3수 안에는 강제되고 2수 안에는 강제되지 않으며, 3수 안에 이기는 첫 수는 `a1-a3^` 하나다 (`tests/test_nano_puzzle.py`).

## DTM 이 긴 판의 독립 확인

DTM 5~20 마다 표본 3개(48개)를 뽑아, solver 를 쓰지 않고 실제 규칙의 탐색으로 **DTM 수 안에는 승패가 강제되고 한 수 적게는 강제되지 않는지** 본다. 모두 풀이와 같았다. `uv run pytest -m slow tests/test_solve_nano.py` 가 풀이를 새로 만들어 다시 확인한다.

| DTM | 탐색 |
| --- | --- |
| 5~9 | 아무것도 기억하지 않고 지나온 경로 그대로 걷는다 |
| 5~20 | 판마다의 답을 기억한다 (`tests/solver_helpers.py` 의 `ForcedWinSearch`) |

- 기억하는 탐색은 지나온 경로를 지운다. 반복이 이기려는 쪽을 돕지 않고, 이기는 수순은 같은 판을 되풀이하지 않는다는 논증에 기댄다(그 docstring). 작은 나노 후보에서는 그대로 걷는 탐색과 답이 같은지 테스트한다.
- 기억하지 않는 탐색은 DTM 12 의 첫 표본에서 300만 국면(133초)을 넘겨 끝내지 못했다.
- 표본이며 전수 확인이 아니다. 무승부 상태의 값은 이렇게 확인하지 않았다.

## 2.5단계 검증에 주는 뜻

시작 국면이 선수 승이라, 시작 국면에서 선수·후수 100판씩 두는 처음의 기준은 판정이 선수 쪽에만 걸리고 시험하는 판이 좁다. 그래서 2026-11-27 에 **풀이에서 뽑은 시험 판 200개와 3수 퍼즐**로 바꿨고, 자가 대국도 도달 가능한 여러 판에서 시작한다. 결정과 층의 구성은 [ADR-0007](adr/0007-nano-verification-uses-trial-positions.md)에 있다.

```
uv run python -m scripts.nano_trials
```

시드 0 의 시험 판은 선수 차례 98개, 후수 차례 102개다.

학습하지 않은 MCTS(균등 정책·가치 0, temperature 0)의 성적 (일회성 스크립트):

- 시작 국면, 탐색 100: 시드 0~99 에서 선수·후수 모두 100패.
- 시험 판 200개, 탐색 100: 76판 통과.
