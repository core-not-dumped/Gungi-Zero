# AlphaZero 하이퍼파라미터를 어떻게 찾을 것인가 (조사, 2026-11-28)

> 2026-11-28 에 나노 군의의 시작 배치를 바꿨다 (ADR-0007). 아래의 성적과 3수 퍼즐은 이전 배치의 것이다.

대상은 2.5단계(나노 군의 검증)이고, 그다음의 미니 군의까지 염두에 둔다. 학습·평가·테스트는 실행하지 않았다. 코드, 저장된 로그, 체크포인트의 파일 시각만 읽었다.

표시: **[자료]** 는 아래 출처에서 읽어 확인한 것, **[저장소]** 는 코드·로그에서 확인한 것, **[계산]** 은 이 문서의 산수, **[추정]** 은 확인하지 않은 판단이다. 출처 번호는 [끝의 목록](#출처)이다.

## 요약

1. 문헌에서 나노 군의에 그대로 옮길 수 있는 "최적값" 은 찾지 못했다. AlphaZero 는 게임마다 튜닝하지 않고 노이즈만 합법수 수에 맞췄고 [1], 작은 게임의 sweep 은 대부분 설정당 1회 실행이다 [8].
2. 지금 가장 먼저 의심할 것은 **새 데이터에 비해 학습이 너무 많은 것**과 **작은 버퍼**다. 1차 학습은 학습 샘플 하나를 약 100번 썼다. KataGo 의 기본 예시는 4다 [4][5].
3. 순서는 (가) 밤샘 학습 채점과 잡음 측정, (나) 진단, (다) 시드를 맞춘 일변수 비교, (라) 필요하면 random search + successive halving 이다. Bayesian optimization 과 PBT 는 지금의 시도 횟수로는 이르다.
4. 시험 판 200개에서 두 신경망의 차이가 10판 안팎이면 우연일 수 있다 (아래 계산). 시드 하나로 설정을 고르지 않는다.
5. 튜닝에는 시험 판 200개가 아닌 **따로 뽑은 개발 판**을 쓴다.
6. 첫 실험에 필요한 명령줄 덮어쓰기, 시험 판만 채점하는 경로, 개발 판은 **아직 코드에 없다**.

## 1. 출발점

**[저장소]** 현재 값 (`scripts/hyperparameters.py`, `ai/training.py`, `ai/mcts.py`)과 1차 학습 (`docs/nano-verification-report.md`, `checkpoints/nano-gungi-seed0-run1.log`):

- 1차(자가 대국 100판/세대, 100세대): 시험 판 149/200, 학습 2,519초, 평가 1,422초. 평가 시간에는 진단(가치 일치율 881,080 상태, 최선수 5,000 국면)이 들어 있다.

- 지금의 200판/세대에서는 새 샘플이 두 배라면 재사용은 약 52, 버퍼는 약 4,900이다 **[추정]**. 밤샘 학습의 실제 샘플 수는 확인하지 않았다.

- 가치 손실 0.006 에 전체 상태 가치 일치율 85.5% 다. 본 국면에 맞춰졌다는 것이 보고서의 **추정**이다.

**[계산]** 시간: 1차는 세대당 약 23초(2,519초에서 따로 잰 상태 열거 216초를 뺌). 밤샘 학습(`night1`)은 5세대 체크포인트(11-27 18:05)에서 1,190세대(11-28 05:45)까지 42,024초로 **세대당 약 35초**다. 같은 때에 Elo 측정이 돌았을 수 있어 단독 속도는 아니다. 학습 200스텝은 CUDA 9.5ms 로 약 1.9초이므로 시간 대부분은 자가 대국이다.

## 2. 탐색 절차

### 2.1 먼저 할 것: 튜닝하기 전

1. **밤샘 학습을 채점한다.** 데이터를 늘린 효과가 먼저 나와야 무엇이 병목인지 안다.
2. **잡음을 잰다.** 마지막 체크포인트 여러 개를 채점해 시험 판 통과 수가 세대 사이에 얼마나 흔들리는지 본다. ELF OpenGo 는 학습 중 모델 강함의 분산이 크고 학습률을 낮춰도 줄지 않았다고 보고한다 [6, §4.2].
3. **실패를 가른다.** 같은 체크포인트를 탐색 100·400·1600 으로 채점한다. 탐색을 늘려 풀리는 판은 신경망이 아주 틀리지는 않은 것이고, 끝까지 안 풀리는 판은 가치·정책 또는 구현(룰·인코딩)을 의심한다 **[추정]**. 이것은 진단이다. 완료 기준의 탐색 100 은 ADR-0007 이 정한 값이다.

### 2.2 탐색 방법 비교

| 방법 | 자료가 말하는 것 | 이 프로젝트에서 |
| --- | --- | --- |
| 수동 일변수 | AlphaGo 는 처음에 값마다 1,000판의 grid 일변수 튜닝을 썼는데 비쌌고, 매개변수가 서로 얽혀 일변수·이변수로는 닿지 못하는 값이 있었다 [7, §1·§3.1] | 첫 단계로 적당하다. 원인을 해석할 수 있다. 얽힌 쌍(버퍼와 재사용, `c_puct` 와 노이즈·탐색 횟수)은 놓칠 수 있다 **[추정]** |
| random search | 영향이 큰 차원이 소수일 때 grid 보다 효율적이다 [11] | 일변수에서 살아남은 3~5개를 함께 흔들 때. **[계산]** 상위 5% 영역을 한 번이라도 뽑을 확률은 `1-0.95^n`: n=14 에서 51%, n=30 에서 79%, n=60 에서 95% |
| Bayesian (GP + EI 등) | AlphaGo 의 **대국 시** 매개변수(주로 MCTS) 3~10개를 후보당 50판으로 평가해 승률을 크게 올렸다 [7]. 학습 하이퍼파라미터를 튜닝한 연구가 아니다. Optuna 의 권장 시도 수는 TPE 약 100~1000, BoTorch 약 10~100 이다 [16] | 학습 한 번이 1시간이면 TPE 의 권장 범위에 못 미친다. 저장한 신경망의 평가 시 `c_puct` 처럼 **싼 목표**에는 쓸 수 있다 |
| successive halving / Hyperband / ASHA | 작은 예산으로 많이 시작해 상위 1/η 만 늘린다. 초반에 구분되지 않는 설정이 많으면 더 많은 예산이 필요하다(n 대 B/n 문제) [12, §3]. ASHA 는 이를 비동기로 바꿔 병렬 작업자에 맞췄다 [13, §3] | random search 와 함께 쓸 만하다. 단 **초반 순위가 최종 순위를 예측해야 한다** (아래 2.5) |
| PBT | 가중치를 복사하며 하이퍼파라미터의 시간표를 찾는다. 개체 10 이하는 분산이 크고 나쁠 수 있으며, 20~40 이면 일관된 개선을 봤다 [14, 개체 수 ablation] | 이 장비에서 학습 20개를 동시에 돌리기 어렵다 **[추정]**. 지금은 제외 |

도구: W&B Sweeps 는 `grid`·`random`·`bayes` 와 Hyperband `early_terminate`(`min_iter` 또는 `max_iter`+`s`, `eta` 기본 3)를 제공하고, bracket 은 **로그한 횟수**로 센다. `bayes` 는 연속 매개변수가 적을 때 맞고 확장이 나쁘다 [18]. Optuna 는 기존 학습 코드를 감싸는 ask-and-tell [17], `SuccessiveHalvingPruner`(ASHA 방식) [20], `HyperbandPruner`(bracket 4~6 권장, TPE 는 bracket 마다 시작 10회 필요) [19] 가 있다. Optuna FAQ 는 병렬 최적화에 SQLite 를 권하지 않고 `JournalStorage` 등을 안내한다 [21]. 어느 쪽이든 중간 지표(학습 중 개발 판 통과 수)를 기록해야 조기 중단이 되는데 지금은 학습이 끝난 뒤에만 잰다 **[저장소]**.

### 2.4 시드와 통계

**시험 판 200개의 우연 [계산]**. 통과 확률 p 인 판이 독립이라고 보는 이항 근사다. 시험 판은 층화 추출이고 서로 독립인지 알 수 없으므로 대략의 크기로만 쓴다.

| 통과 수 | 표준오차(판) | 95% Wilson 구간(판) |
| ---: | ---: | --- |
| 149 | 6.2 | 136~160 |
| 180 | 4.2 | 170~187 |
| 190 | 3.1 | 182~194 |
| 200 | - | 196~200 |

- 두 신경망을 **독립 표본처럼** 비교하면 차이의 95% 폭은 p=0.75 에서 약 ±17판, p=0.90 에서 ±12판, p=0.95 에서 ±9판이다.
- 실제로는 **같은 200판**을 두므로 짝 비교가 맞다. A 만 통과한 수 b, B 만 통과한 수 c 에 정확 McNemar(이항 0.5) 검정을 한다. `verify_nano` 의 `failed_trials` 로 계산할 수 있다.

| 갈린 판 b+c | 양측 p<0.05 에 필요한 최소 \|b−c\| |
| ---: | ---: |
| 10 | 8 (9 대 1) |
| 20 | 10 (15 대 5) |
| 30 | 12 (21 대 9) |
| 40 | 14 (27 대 13) |
| 60 | 18 (39 대 21) |

- 이 검정은 **그 두 가중치**의 차이만 말한다. **설정**의 차이를 말하려면 학습 시드를 반복해야 한다. 평가는 temperature 0 과 고정 시드라 같은 가중치에서는 거의 결정적이고, 큰 변동은 학습에서 온다 **[추정]**.
- 같은 설정이라도 시드 5개씩의 두 묶음이 통계적으로 다른 분포처럼 보일 수 있었다 [22, "Random Seeds and Trials"]. 권고는 Welch t-검정, 0.05 보다 낮은 유의수준, 다중 비교 보정, 표준편차를 재는 예비 실험 20회 이상, 검정력 계산보다 많은 표본이다 [23, Final recommendations]. 실행이 적을 때는 구간 추정과 IQM 보고가 권장된다 [24, 초록].

**필요한 시드 수 [계산]** (설정당, 정규 근사, 양측 5%, 검정력 80%, `n = 2·(1.96+0.84)²·σ²/δ²`). σ 는 시드 사이의 통과 수 표준편차로 **아직 재지 않았다**. 작은 n 에서는 t 보정으로 1~2개가 더 필요하다.

| σ \ 찾고 싶은 차이 δ | 5판 | 10판 | 20판 |
| ---: | ---: | ---: | ---: |
| 3 | 6 | 2 | 1 |
| 5 | 16 | 4 | 1 |
| 8 | 41 | 11 | 3 |

현실적인 규칙 **[추정]**:

- 걸러내기: 설정당 시드 3개(0,1,2 를 모든 설정에 똑같이). 평균 차이가 10판 이상이고 시드 3개의 방향이 같으면 다음 단계로 보낸다. 이것은 선별이지 증명이 아니다.
- 확정: 고른 설정과 기준 설정을 **새 시드** 5개 이상으로 다시 돌린다.
- 설정을 k 개 비교해 최고를 고르면 그 점수는 낙관적이다. **[계산]** 차이가 전혀 없는 k 개의 정규 잡음에서 최댓값의 기댓값은 k=5 에서 1.16σ, 10 에서 1.54σ, 20 에서 1.87σ 다.
- 한 실행에서 체크포인트를 시험 판 점수로 골라 "최고 점수" 를 보고하지 않는다. 마지막 몇 체크포인트의 평균으로 비교한다.

**200/200 의 어려움 [계산]**: 판마다 독립이라면 200판을 모두 통과할 확률은 판당 99% 에서 13%, 99.5% 에서 37%, 99.9% 에서 82% 다. 평균을 올리는 튜닝만이 아니라 남는 실패 판의 원인 분석이 필요하다.

### 2.5 조기 중단

- 1차의 추이는 68(1세대)→118(5)→120(10)→138(25)→144(50)→149(100)다 **[저장소]**. 초반이 가파르고 뒤의 개선은 위의 잡음과 같은 크기다.
- 그래서 처음에는 **명백한 실패만** 중단한다 **[추정]**: 손실이 NaN, 20세대 이후에도 학습하지 않은 MCTS(76/200, ADR-0007) 근처, 자가 대국이 한 결과로 붕괴.
- successive halving 을 쓰려면 먼저 완주한 실행 10개 안팎에서 중간 시점 순위와 최종 순위의 일치를 확인한다. 학습을 적게 하는 설정, 큰 버퍼, 큰 신경망은 늦게 오를 수 있어 일찍 버리면 손해다 **[추정]**. 맞는다면 η=3, 예를 들어 20분 → 1시간 → 3시간.
- 학습 손실로 중단하지 않는다. 설정이 다르면 타깃 분포가 다르고, 작은 게임 연구에서도 학습 중 손실·Elo 와 최종 대회 Elo 가 어긋난 경우가 보고됐다 [9, 결론].

### 3.1 재사용 비율, 버퍼, 자가 대국 수

- KataGo 의 본 학습은 샘플 2.41억 개에 학습 9.54억 샘플(약 4배)이다 [4, Table 6]. 저장소 문서는 `max-train-bucket-per-new-data` 예시 4를 보수적이라 부르고, 올리면 빠르지만 과적합 위험이 있다고 쓴다. 또 자가 대국에 학습의 4~40배 GPU 를 쓰라고 한다 [5].
- 대국 수 대 미니배치 수의 비는 AGZ 7:1, AZ 30:1, ELF OpenGo 13:1 이고, ELF 는 10:1 아래로 크게 내리면 학습을 방해했다(아마 과적합)고 쓴다 [6, §3·Appendix A]. 배치 크기와 대국 길이가 달라 이 비를 **그대로 옮길 수 없다**. 참고로 우리는 200판 대 200스텝, 1:1 이다 **[저장소]**.
- MuZero 는 상태당 0.1 샘플을 뽑았고, Reanalyze 변형(Atari)은 저장한 국면을 최신 가중치로 다시 탐색해 정책 타깃의 80%를 갈고, 상태당 2.0 샘플, 가치 손실 가중 0.25 로 과적합을 피했다 [3, Appendix H]. Reanalyse 비율로 데이터 예산을 조절하는 후속 연구도 있다 [10, §3~4]. 여기서는 다시 탐색하는 비용이 자가 대국 탐색과 같은 종류라 먼저 할 일은 아니다 **[추정]**.
- 버퍼: AGZ 는 최근 50만 판 [2, Methods "Optimisation"]. KataGo 는 25만 샘플에서 시작해 준선형으로 약 2,200만까지 늘렸다 [4, §2·Appendix C]. 우리 버퍼는 2,000판, 수천 샘플이다. 절대값은 게임 크기가 달라 옮기지 않고, "데이터가 쌓이면 창도 키운다" 를 가져온다 **[추정]**.
- 6×6 Othello 의 sweep 은 대체로 값이 클수록 강했지만, 예산이 한정되면 내부 반복(탐색, 대국, epoch)보다 **바깥 반복(세대)** 을 늘리는 것이 나았고, 학습을 더 해서 오히려 약해진 경우(과적합으로 추정)를 보고한다 [9, §6~7]. sweep 부분은 설정당 1회 실행이다 [9, §5].

### 3.2 탐색 횟수

- AZ 800, AGZ 1,600 [1][2]. KataGo 는 가치에는 판이 많은 것이, 정책에는 탐색이 깊은 것이 필요하다는 긴장을 풀려고 일부 수(p=0.25)만 큰 탐색(N=600→1000)을 하고 기록하며 나머지는 작은 탐색(n=100→200)을 한다. 이 기법을 빼면 같은 Elo 에 1.37배의 시간이 들었다 [4, §3.1·Table 2].
- ELF OpenGo 는 최종 모델에서도 대국 시 탐색을 두 배로 하면 크게 강해졌다 [6, §5.4]. 대국 시의 결과이지 학습 시의 권장값은 아니다.
- 보통의 AlphaZero 는 루트의 모든 행동을 방문하지 못할 만큼 탐색이 적으면 정책이 나아지지 않을 수 있다. Gumbel 방식은 비복원 추출로 이를 고친다. 9×9 바둑에서 MuZero 는 16 이하에서 학습에 실패했고 Gumbel MuZero 는 2에서도 학습했다(시드 2개) [15, §7·Figure 2]. mctx 는 `gumbel_muzero_policy` 를 권장한다 [25].
- 나노 군의의 평균 합법수는 9.2라 100회는 합법수의 약 11배다. 늘리는 것보다 줄여서 판을 더 만드는 쪽도 시험할 값이 있다 **[추정]**. Gumbel 은 5단계의 계획이다.

### 3.3 `c_puct` 와 방문하지 않은 수의 가치

- AGZ·AZ 의 2017 본문은 `c_puct` 값을 쓰지 않았고(AGZ 는 Gaussian process 로 골랐다고만 한다) ELF 는 시험한 값 가운데 1.5 가 뚜렷이 좋았다 [2, Methods 의 "Self-Play Training Pipeline" 바로 앞][6, §5.1·Figure 6]. KataGo 는 1.1 [4, §2]. AZ 2018 은 `C(s) = log((1+N+c_base)/c_base) + c_init` 이며 학습 때의 빠른 대국에서는 사실상 상수라고 쓴다 [26, Methods "Search"].
- MuZero 의사코드는 `pb_c_init=1.25`, `pb_c_base=19652` 이고, 보드 게임에서는 Q 를 `[-1,1]` 의 알려진 범위로 **`[0,1]` 에 정규화**해 쓰며, 방문하지 않은 자식의 가치 항은 0 이다 [27, `ucb_score`, `MinMaxStats`].
- **[저장소 + 계산]** 우리는 Q 가 `[-1,1]` 인 채로 1.25 를 쓴다. Q 의 폭이 두 배이므로 MuZero 의 척도로는 약 0.625 에 해당하고, 같은 균형은 2.5 다. 그래서 2.5 가 첫 후보다. 어느 쪽이 좋은지는 실험으로만 안다.
- **[저장소]** 방문하지 않은 수의 가치는 0(무승부)이다. MuZero 척도의 0 은 최솟값(패)이다. KataGo 는 부모 가치에서 이미 방문한 자식들의 정책 질량에 따라 커지는 양을 깎고(`c_FPU=0.2`), 노이즈가 켜진 루트에서는 깎지 않는다 [4, §2 각주 3]. `ai/mcts.py` 를 바꿔야 하는 비교다.
- Othello sweep 에서는 `c_puct` 0.5·1.0·2.0 가운데 지표에 따라 좋은 값이 엇갈렸다 [8, Table 3].

### 3.4 Dirichlet 노이즈

- ε=0.25, α 는 전형적인 합법수 수에 반비례: 체스 0.3, 장기(shogi) 0.15, 바둑 0.03 [1, Methods "Configuration"]. KataGo 는 `α = 0.03 × 19² / (합법수 수)`, 곧 총합 약 10.8 [4, §2]. 우리의 `10 / 평균 합법수` 는 같은 규모다.
- 노이즈로 늘어난 방문이 정책 타깃에 섞인다. KataGo 의 forced playouts + policy target pruning 은 탐험과 타깃을 분리하며, 빼면 1.25배 느렸다 [4, §3.2·Table 2]. 우리 타깃은 노이즈가 든 방문 분포 그대로다 **[저장소]**.

### 3.5 temperature

- AGZ 는 첫 30수 τ=1, 이후 0에 가깝게 [2, Methods "Self-Play"]. MuZero 의사코드도 같다 [27]. KataGo 는 0.8에서 0.2로 부드럽게 내린다(반감기 = 판 너비) [4, Appendix D]. ELF 는 논문의 모호함을 지적하고 학습 데이터의 정책에 τ=1 을 모든 수에 썼다 [6, §3].
- **[저장소]** 틱택토에서는 모든 수를 temperature 1 로 둔 것이 가치 일치율을 0.5 안팎에서 0.76 으로 올렸다. 나노의 시험 판은 긴 승리 수순에서 약하고(DTM 13 이상 14/40), 4수 뒤의 탐욕 선택이 긴 대국의 다양성을 줄일 수 있다 **[추정]**. 다만 대국이 평균 2.5수라 영향받는 판은 소수일 수 있다.
- 다양성은 temperature 만이 아니다. KataGo 는 대국 분기와 다양한 시작을 쓴다 [4, Appendix D]. 우리의 `NANO_GUNGI_INITIAL_START_FRACTION=0.25` 는 ADR-0007 의 결정이라 바꾸려면 ADR 을 고친다. 풀이(DTM·이론값)로 시작 판을 고르는 것은 금지다.

### 3.6 학습률, 신경망

- AZ 는 SGD, 배치 4,096, 학습률 0.2 에서 세 번 낮춤 [1]. ELF 는 학습률을 10⁻⁵ 까지 더 낮춰도 개선이 거의 없고 불안정했으며 버퍼를 키워야 할 수 있다고 본다 [6, §6]. 옵티마이저와 규모가 달라 숫자는 옮기지 않는다.
- ELF 는 BatchNorm 통계가 낡아 성능이 떨어지는 문제를 보고했다 [6, Appendix C]. 우리 신경망도 BatchNorm 을 쓴다. 영향은 확인하지 않았다.
- L2 계수 1e-4 는 AGZ 와 같다 [2]. KataGo 는 3e-5 [4, §2].
- KataGo 는 작은 신경망으로 시작해 키웠다 [4, §2]. 나노에서는 가치 손실이 0.006 까지 내려가므로 용량이 먼저 부족하다는 증거는 없다 **[추정]**. 큰 신경망은 자가 대국도 느리게 만든다.
- AGZ 계열의 gating 은 AZ 에서 빠졌다 [1]. 우리도 없다. KataGo 문서는 선택 사항으로 두되 초기 디버깅에 도움이 된다고 한다 [5].

## 4. 시험 판을 튜닝 목표로 쓰는 문제

- 같은 검증 셋의 결과를 보고 설정을 거듭 고르면 그 셋에 과적합할 수 있다 [28, §1]. 선택 기준의 분산 때문에 생기는 낙관 편향은 알고리즘 사이의 차이만큼 클 수 있다 [29, 초록]. [28] 은 holdout 의 답에 잡음·문턱을 두어 재사용하는 Thresholdout 을 제안한다. 여기서는 판을 새로 뽑을 수 있으므로 분리가 더 단순하다 **[추정]**.
- 학습에 풀이를 쓰지 않아도, 시험 판 점수로 고른 하이퍼파라미터를 통해 정답이 간접으로 새어 든다.

대책:

1. **개발 판**: 같은 층 구성, 다른 시드로 뽑고 시험 판 200개의 정규형 `board_key` 를 뺀다. 튜닝·조기 중단·체크포인트 비교는 개발 판으로만 한다. `select_trials` 에는 제외 인자가 없어 코드가 필요하고, 모든 층에 후보가 충분한지는 확인하지 않았다.
2. **시험 판 200개는 확정한 설정에만** 쓴다. 몇 번 썼는지, 어떤 설정이었는지 모두 기록한다. 통과할 때까지 시드를 바꿔 재채점해 하나를 고르지 않는다. 통과 판정에 쓸 학습 시드의 규칙을 미리 정한다.
3. 지금까지의 실패 판 순번을 보고 고친 것이 있으면 그 사실을 보고에 남긴다.
4. 2.5단계의 목적은 버그 검출이다(ADR-0007). 특정 설정에서만 통과하면 그것도 보고한다.
5. **미니 군의에는 풀이가 없다.** 거기서 쓸 지표(고정한 체크포인트 묶음, 랜덤 AI, 탐색 AI 와의 대국)를 나노에서 함께 기록해 시험 판 점수와 같이 움직이는지 본다. 1차에서는 시험 판이 120→149 로 오르는 동안 Elo 는 평평했다(시작 판을 바꾸기 전의 값) **[저장소: 보고서]**. 학습 중의 상대 Elo 는 대회 Elo 와 다를 수 있고 [9, 결론], 연속 모델끼리의 Elo 는 부풀며 퇴화를 놓칠 수 있다 [6, §4.2].

## 5. 속도 개선과 탐색 예산

하이퍼파라미터가 아니지만 같은 시간의 실행 수를 바꾼다. 저장소의 원칙(속도는 검증 후 측정하고 진행)과 4단계 계획이 있으므로, 앞당길지는 따로 정한다.

| 항목 | 근거 | 필요한 것 |
| --- | --- | --- |
| 자가 대국을 CPU 로 | **[저장소: 측정]** 평가 1회 CPU 0.47ms, CUDA 0.9ms. 학습 1스텝 CUDA 9.5ms, CPU 37ms | **[계산]** 세대 35초 중 자가 대국 약 33초가 모두 이 비율로 줄면, 전부 CPU 로는 약 17+7.4=25초, 자가 대국 CPU + 학습 CUDA 는 약 19초. `--device cpu` 는 지금 된다. 장치 분리는 코드 필요 |
| 실행 여러 개를 CPU 에서 동시에 | `rate_nano` 가 이미 프로세스당 torch 스레드 1로 나눈다 **[저장소]** | 총 처리량은 크게 늘 수 있다 **[추정]**. 동시 실행 시 속도 저하와 메모리(프로세스마다 상태 목록)는 재지 않았다. 스레드 수를 고정해야 한다 |
| 여러 판 동시 진행 + 배치 추론 | ELF 는 V100 에서 배치 16까지 거의 선형, 128까지 준선형의 처리량 증가를 봤다 [6, Appendix A]. AZ 도 병렬 대국의 국면을 묶었다 [26, "Configuration"] | 4단계 작업. RTX 4060 과 이 작은 신경망의 배수는 모른다. Python 트리 연산이 차지하는 비중도 재지 않았다 |
| 상태 열거·시험 판 캐시 | 2.3절 | 작은 코드 |
| 시험 판만 채점 | 지금 평가는 진단까지 한다 | 작은 코드 |
| playout cap randomization, tree reuse | [4, §3.1], AGZ 는 하위 트리를 재사용 [2, "Play"] | 학습 동작이 바뀌므로 하이퍼파라미터처럼 비교해야 한다 |

속도를 바꾸면 최적값도 움직일 수 있다. AlphaGo 는 하드웨어가 바뀐 뒤 기존 매개변수의 최적값이 달라졌다 [7, §3.3]. 큰 속도 변경 뒤에는 `simulations` 와 재사용 비율을 다시 본다.

| **CUDA graph (묶음 64로 고정해 재생)** | **0.60** | 4e-8, 7e-6 |

한 세대의 자가 대국이 신경망에 묻는 판 가운데 앞에서 이미 물은 것: 나노(200판) 44,482번 중 서로 다른 판 6,814개로 **85% 가 반복**, 미니(32판, 학습 안 함) 31% 가 반복. 가중치가 고정된 세대 안에서는 답을 기억해 두면 같은 결과다.

### 답 기억과 CUDA graph 구현 뒤의 측정 (2026-11-28)

`evaluation_cache`·`cuda_graph` (`ai/batched.py`, `ai/graphed.py`). 나노의 실제 설정(200판/세대, 64판 동시)을 10세대씩, 시작 판은 무작위로 만든 3,000판에서. 게임(League of Legends)이 함께 돌았다. 조합마다 한 번씩이다.

| 조합 | 초/세대 (2세대부터) | 자가 대국 초/세대 |
| --- | ---: | ---: |
| 묶음만 | 22.4 | 21.7 |
| + 답 기억 | 12.3 | 11.6 |
| + CUDA graph | 13.3 | 11.9 |
| **둘 다** | **11.3** | 9.8 |

둘 다 켠 30세대에서 GPU 메모리 예약량은 56 MiB 로 그대로였고, 세대마다 새로 기록한 평가기와 그대로의 신경망의 출력 차이는 5.7e-6 이하였다. 자가 대국의 평가 요청 가운데 기억으로 답한 몫은 62~84% 다.

합성곱과 BatchNorm 을 합치는 것(`fuse_conv_bn_eval`, 코드에 넣지 않았다)을 묶음 10의 호출 한 번으로 쟀다: 나노 CUDA graph 0.39 → 0.31ms, 미니 0.54 → 0.50ms. 출력 차이 4e-5 이하.

### 그다음 병목 (2026-11-28, 일회성 프로파일과 시험, 코드에 넣지 않았다)

답 기억과 CUDA graph 를 켠 자가 대국의 cProfile (게임이 함께 도는 상태):

| 부분 | 나노 | 미니 |
| --- | ---: | ---: |
| 룰 엔진 (`engine/`) | 54% | 51% |
| MCTS 트리 | 15% | 7% |
| 게임 어댑터 (encode, 행동 인덱스) | 11% | 9% |
| torch / GPU | 6% | 20% |
| 그 밖 | 14% | 13% |

`RuleEngine._evaluate_board` 의 결과를 `(board, side)` 마다 기억하는 시험(`lru_cache`): 자가 대국 시간 나노 8.9 → 5.5초, 미니 25.3 → 17.9초 (3번 중 가장 빠른 값). 둔 수는 모두 같았다. 판 평가 요청의 98%(나노)·81%(미니)가 이미 본 판이다. 지금은 `outcome`·`legal_moves`·`apply_move` 의 검사가 같은 판을 되풀이해 평가한다.

### 룰 엔진 쪽 개선의 구현과 측정 (2026-11-28)

셋을 코드에 넣었다. 여러 변형의 랜덤 대국 92,232 국면에서 합법수와 순서, 승패, 종료 사유, 행동 인덱스, 텐서가 바꾸기 전 코드와 같았다 (일회성 대조). 자가 대국 64판 동시, 답 기억 포함, 세 번 중 가장 빠른 값(초). "CPU" 는 균등 신경망이라 룰과 탐색의 시간이고, GPU 는 CUDA graph 를 쓴다. 뒤의 측정은 게임이 함께 돌아 흔들린다.

| 단계 | 나노 CPU | 나노 GPU | 미니 CPU | 미니 GPU |
| --- | ---: | ---: | ---: | ---: |
| 바꾸기 전 (게임 없음) | 8.59 | 12.97 | 5.06 | 5.88 |
| 1. 판 + 차례의 규칙 결과 기억 | 5.21 | 7.77 | 4.12 | 4.77 |
| 2. 이동 경로 표 (두 번) | 4.94, 5.68 | 6.32, 6.98 | 2.18, 2.58 | 3.08, 3.34 |

- 1 과 2 를 번갈아 두 번씩 잰 CPU 값은 나노 6.02·6.03 → 5.50·5.69, 미니 3.64·3.38 → 2.73·2.70 이다.
- 4 의 효과는 흔들림 안이라 확인하지 못했다.

## 확인하지 못한 것

- AlphaZero 2018 의 **의사코드**(Science 보충 자료) 는 읽지 못했다. 버퍼 크기, 방문하지 않은 수의 가치, `c_base`·`c_init` 의 AZ 값은 여기서 인용하지 않았다. 19652 와 1.25 는 MuZero 의사코드의 값이다.
- AlphaZero 의 Science 게재본 자체는 읽지 않았고 DeepMind 가 공개한 사전 공개본 [26] 을 읽었다. AGZ 는 UCL 저장소의 저자본이다.
- Gumbel 논문 [15] 은 OpenReview 가 사람 확인 화면을 띄워 원본을 읽지 못했다. **제3자가 올린 텍스트 변환본**을 요약 도구로 읽었다. 인용한 수치는 원본과 대조해야 한다.
- Optuna [16][19][20][21][17], W&B [18], mctx [25], KataGo 저장소 문서 [5], MuZero 의사코드 [27], [24] 의 초록은 요약 도구를 거쳐 읽었다.
- 시드 사이의 σ, 시험 판 전용 채점 시간, CPU 병렬 실행의 처리량, 배치 추론의 배수, 개발 판 후보의 충분성, 밤샘 학습의 결과는 재지 않았다.
- 3절의 우선순위와 시험 값은 이 저장소에서 검증한 것이 아니다.
