# `encode` 속도: 판만 회전하기 전과 후 (2026-11-27)

`Gungi.encode` 는 후수 차례 국면에서 `canonical` 을 불렀고, `canonical` 은 **경로 전체**를 180°
돌려 새로 만든다. 텐서에는 지금 판만 필요하므로, 지금은 `encode` 가 칸 번호만 돌려 읽는다.

## 결과

호출당 µs. 전은 `fbb477b` 의 엔진, 후는 이 변경이다. 같은 컴퓨터에서 한 번씩 돌렸고, 값마다
다섯 번 잰 것 중 가장 빠른 것이다.

- 후수 차례의 `encode` 가 빨라졌다. 미니 군의 ply 199 에서 1781 → 27.8 µs (약 64배)이고,
  선수 차례와의 차이가 거의 없어졌다.
- 미니 군의의 선수 차례는 1~2 µs 느려졌다. 말마다 좌표를 `engine.geometry` 에 묻는 비용이다.
- 남은 `encode` 비용이 ply 에 비례하는 것은 반복 횟수를 세느라 경로를 걷기 때문이다.
- **`canonical` 은 빨라지지 않았다.** 정규형 국면은 반복 횟수를 보존해야 해서 경로를 돌린다.
  후수 차례에서는 여전히 ply 에 비례해 비싸다. 선수 차례의 0.2 → 0.4 µs 는 정규형 표시를 단
  객체를 새로 만드는 비용이다.
- 그래서 MCTS 가 노드마다 `canonical` 을 부르면 이 변경의 이득이 사라진다. `encode` 는 원래
  국면에 바로 부를 수 있다. 합법수 마스크는 원래 국면의 인덱스를
  `to_canonical_action_index` 로 옮기면 된다. 2단계 설계에서 정한다.

## 재현

```
uv run python -m scripts.encode_benchmark
```

전 값은 같은 스크립트를 변경 전 코드에서 돌린 것이다. 긴 경로는 같은 네 수를 되풀이해 만들고,
반복 한도와 수 제한만 1000 으로 늘렸다.

## 출력이 같은지

시드 0~399 의 랜덤 대국을 네 설정(帥만, 1단, 미니, 나노)에서 두며 모든 국면의 렌더, 정규형
렌더, `encode`, 합법수 순서와 정규형 행동 인덱스를 해시했다. 전후의 해시가 같았다. 일회성
스크립트로 확인했다.
